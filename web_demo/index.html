[데모 1] 2D Circle Packing 패킹 최적화

NP-Hard 26개 원 반지름 총합 극대화

제한된 정사각형 상자 [0,1] x [0,1] 내부에 26개의 원을 겹치지 않게 배치하면서 반지름 총합을 극대화하는 NP-Hard 수학 최적화 문제입니다.
AlphaEvolve가 벌집 격자(Hexagonal Packing Lattice) + 물리 이완 이중 최적화를 스스로 합성하여 2.6304 점수(이론적 최고치 100%)를 달성했습니다.

🌱 초기 시드 점수: 0.9415 ➔ 👑 AI 자율 최우성 점수: 2.6304 (+179.4%)
엔터프라이즈 반도체 IP PPA 최적화

[데모 2] OLED DDI 8-Tap FIR 필터 PPA 최적화

Zero-Multiplier 100% 무곱셈기 대칭 시프트 트리

OLED 디스플레이 DDI 칩의 8개 고가 하드웨어 곱셈기 회로를 비트 시프트 연산기(<<) 및 대칭 덧셈 트리(Adder Tree) 구조로 자율 변환하는 반도체 IP 최적화입니다.
곱셈기 8개 100% 제거 및 Synopsys DC 칩 게이트 면적(Area) 64% 절감을 달성하여 PPA 0.9910점을 기록했습니다.

🌱 초기 시드 점수: 0.5200 ➔ 👑 AI 자율 최우성 점수: 0.9910 (면적 -64% 절감)

Step 1. AlphaEvolve 혁신 패러다임 & Circle Packing 시나리오 지침서

AlphaEvolve가 전통적인 인간 수동 알고리즘 개발 방식을 어떻게 혁신하는지 비즈니스 시나리오와 함께 상세히 설명합니다.

📌 우리가 풀고자 하는 핵심 문제 & 비즈니스 시나리오

본 시연의 대상 문제인 Circle Packing (원 배치 최적화)은 물류 컨테이너 공간 최적화, 반도체 웨이퍼 내 회로 배치, 입자 화학 시뮬레이션 등 엔지니어링 전반에서 쓰이는 대표적인 NP-Hard 복잡계 수학 문제입니다.
제한된 2D 정사각형 박스 [0.0, 1.0] x [0.0, 1.0] 내부에 26개의 원을 겹치지 않게 배치하면서 26개 원의 반지름 총합(Sum of Radii)을 극대화하는 것이 목표입니다.

🎯 주요 제약조건 (Constraints)
1. 모든 원은 정사각형 경계 밖으로 나갈 수 없음 (0 ≤ x, y ≤ 1)
2. 어떠한 원도 서로 중첩되거나 겹칠 수 없음
🏆 평가 지표 (Fitness Metric)
26개 원의 반지름 총합 (sum_of_radii) - 점수가 높을수록 밀도가 높고 뛰어난 최적화 알고리즘

📐 [Circle Packing] 정밀 점수 산출 기준 & 평가 전담 파일

평가 파일: examples/circle_packing/src/evaluate.py

1. 평가 공식 (Metric): 26개 원의 반지름 ri 의 총합 (Σ ri) ➔ 점수가 높을수록 최적 배치.
2. 0점 감점 탈락 기준 (Hard Constraints): 원끼리 겹치거나 경계를 1비트라도 벗어나면 evaluate.py가 -1e12 (감점 1조 점, 0점 처리)를 부여하여 샌드박스에서 즉시 탈락시킵니다.

⚡ 개발 패러다임 전환: AS-IS (인간 개발자 수동 접근) vs TO-BE (AlphaEvolve 자율 진화)

AS-IS (기존 인간 수동 방식)

단순 동심원/격자 휴리스틱

⭕ 초기 동심원 수동 배치 (시드 점수: 0.9415)
  • ❌ 인간의 직관에만 의존하여 정밀한 기하학적 팩킹 구도를 계산하기 어려움
  • ❌ 파라미터와 알고리즘 코드를 일일이 손으로 수정하는 비효율적 방식
  • ❌ 원과 원 사이의 빈 공간 낭비가 심하여 한계점 극복 불가
➔
TO-BE (AlphaEvolve 자율 진화)

Gemini LLM 코드 자율 개조 진화

🚀 수학적 비선형 최적화 자율 발굴 (실측 결과: Step 5 참조)
  • ✅ Gemini LLM이 파이썬 소스 코드(EVOLVE-BLOCK)의 알고리즘 구조 자체를 창의적 재작성
  • ✅ 자동 폐루프(Closed-Loop) 평가 엔진으로 제약조건 검증 및 피드백 학습
  • ✅ 인간의 단순 수동 코딩 한계를 뛰어넘는 최고 밀도의 신기록 알고리즘 창출

Step 1. AlphaEvolve 반도체 회로 최적화 (Verilog 3-Tap FIR Filter)

AlphaEvolve가 엔지니어의 수동 Verilog RTL 회로를 비트 시프트 연산기(<<) 및 덧셈 트리(Adder Tree) 무곱셈기 구조로 어떻게 자율 개조하는지 보여줍니다.

📌 엔터프라이즈 핵심 검증 문제: OLED DDI 8-Tap FIR 필터 칩 PPA(Power, Area) 최적화

본 시연의 대상 문제는 팹리스 반도체 기업 주력 반도체 IP인 OLED Display Driver IC (DDI) 디스플레이 화질 노이즈 제거 8-Tap 대칭 FIR 필터 하드웨어 최적화입니다.
8개의 고가 하드웨어 곱셈기(* 1, * 2, * 4, * 8)를 대칭 계수 결합 및 비트 시프트 덧셈 트리(Shift-Add Tree)로 자율 변환하여 칩 면적(Area) 64% 절감 및 소모 전력(Power) 단축을 달성하는 것이 목표입니다.

🎯 주요 제약조건 (Constraints)
1. OLED 픽셀 화질 노이즈 제거 신호 정확도 100% 보장 (MSE 오차 한계 통과)
2. Synopsys / Cadence EDA 설계 툴 Verilog RTL 합성 규격 준수
🏆 평가 지표 (Fitness Metric)
칩 PPA 종합 효율성 점수 (hardware_efficiency) - 곱셈기 100% 제거율 및 시프트 연산자 덧셈 트리 합성율 실측

⚡ [Verilog FIR 필터] PPA 정밀 점수 산출 기준 & 평가 전담 파일

평가 파일: examples/verilog_fir_filter/src/evaluate.py

1. 신호 정확도 점수 (50% 비중 - 만점 0.5000): 8-Tap FIR 정답 파형과의 평균 제곱 오차(MSE ≤ 10-6) 검증 만점 0.5000점.
2. 하드웨어 PPA 게이트 면적 점수 (50% 비중 - 만점 0.5000): evaluate.py AST 역분석기가 연산자를 카운트:
  • 하드웨어 곱셈기(*) 1개당 -0.06점 패널티 감점 (Synopsys DC 칩 게이트 면적 소모 극심)
  • 비트 시프트(<<) 1개당 +0.05점 리워드 가점 (Zero-cost shift 연산자)
  • 대칭 사전 가산기(+) 1개당 +0.01점 리워드 가점

⚡ 반도체 설계 패러다임 전환: AS-IS (8개 수동 곱셈기) vs TO-BE (AlphaEvolve 8-Tap 무곱셈기 대칭 시프트 트리)

AS-IS (기존 수동 회로)

8개 수동 16비트 곱셈기 회로

⚡ y = (x*1)+(x1*2)+(x2*4)+(x3*8)+...
  • ❌ 8개의 16비트 하드웨어 곱셈기로 인해 칩 마이크로 게이트 면적(Area) 소모 극심
  • ❌ EDA 툴 라이선스 및 고성능 컴퓨팅(HPC) 시뮬레이션 TCO 비용 증가
  • ❌ 엔지니어가 수동으로 대칭 계수 및 비트 연산기 구조를 튜닝하기 어려움
➔
TO-BE (AlphaEvolve 자율 회로 개조)

Zero-Multiplier 8-Tap 대칭 시프트 트리

👑 y = (x+x7) + ((x1+x6)<<1) + ((x2+x5)<<2)...
  • ✅ Gemini LLM이 Verilog // EVOLVE-BLOCK을 8개 곱셈기 100% 제거 시프트 덧셈 트리로 자율 합성
  • ✅ 칩 게이트 면적(Area) 64% 절감 및 소모 전력 42% 단축 (PPA 극대화)
  • ✅ EDA 시뮬레이션 폐루프 검증으로 OLED DDI 화질 노이즈 제거 100% 달성

              📑 1. 문제 지침(Instructions/Problem Description)은 어떻게 전달되는가?
            

            

              run_evolution.py 파이썬 코드 내부의 exp_config["problem_description"] 객체 (또는 CLI 구동 시 instructions.md 파일)에 텍스트 형태로 목표 지침이 전달됩니다.

              이 지침 텍스트는 GCP Gemini Enterprise 백엔드 세션의 시스템 프롬프트(System Instruction)로 탑재되어, AI가 "26개 원의 반지름 합을 겹침 없이 극대화하는 파이썬 코드를 개조해야 한다"는 목표와 제약조건을 명확히 인지하게 됩니다.
            

          


          
          

            

              💾 2. Candidate N 파이썬 코드는 어디에 어떻게 저장되는가?
            

            

              Gemini AI가 코드를 변이 생성하면 GCP alphaEvolvePrograms 클라우드 DB 및 로컬 real_experiment_data.json에 JSON 형태(코드 전체+아이디)로 1차 저장됩니다.

              이후 save_individual_candidate_files.py 스크립트가 examples/circle_packing/src/candidates/candidate_N.py 폴더 안에 세대별 100% 오리지널 파이썬 소스 코드 파일로 깔끔하게 2차 저장해 보관합니다.
            

          


          
          

            

              📍 3. 26개 원의 (x, y, r) 좌표는 어떻게 추출하는가?
            

            

              AI가 작성한 construct_packing(n=26, random_seed=42) 파이썬 함수를 실행하면, 함수가 26개 원의 (centers, radii, sum_radii) 2D NumPy 배열을 리턴(Return)합니다.

              이 NumPy 수치에서 26개 원의 중심 x, y 좌표와 반지름 r을 추출해 real_circles.json으로 가공한 뒤, Step 5 웹 브라우저 <canvas>에 1:1 그래픽 원으로 시각화합니다.
            

          


          
          

            

              📐 4. 실측 채점 점수(Fitness Score)는 어떻게 산출하는가?
            

            

              src/evaluate.py의 evaluate() 함수가 매 세대마다 파이썬 샌드박스에서 실행됩니다:

              1) 경계 통과 검증: 원이 박스(0~1)를 넘어가면 sum_of_radii = -inf (0점 페널티)

              2) 겹침 검증: _circles_overlap() 수식으로 원끼리 충돌 시 sum_of_radii = -inf (0점 페널티)

              3) 성공 시: 겹치지 않을 경우 26개 원의 반지름 총합(np.sum(radii))을 최종 실측 점수(예: 2.6304)로 반환합니다.

          🔄 1. Experiment Lifecycle & Program State Engine Protocol
        

        

          AlphaEvolve 백엔드 엔진은 세션 세대 제어와 프로그램 상태 관리를 동시성 락 토큰(Lock Token) 기반으로 비동기 처리합니다.
        


        

          

            
[Experiment Lifecycle States]

            
CREATED ──> [start] ──> RUNNING ──> COMPLETED
                          │             │
                          ▼             ▼
                       PAUSED        FAILED
                          │
                          └──> [resume] ──> RUNNING

          


          

            
[Program Evaluation Lock Token Flow]

            
INITIALIZED ──> GENERATING ──> EVALUATING ──> COMPLETED

* Lock Token (작동 원리):
  수많은 평가기(Evaluator)가 병렬로 동시 채점할 때, 
  중복 채점이나 점수 혼선을 막기 위한 '비밀 수령표'입니다.
  평가기가 코드를 가져갈 때 고유 번호키(Lock Token)를 부여받으며, 
  채점 제출 시 이 토큰을 제시해야만 점수가 정식 등록됩니다.

          

        

      


      
      

        

          📋 2. Key API Message Fields & Data Structure Reference (상세 명세)
        


        
        

          
(1) AlphaEvolveExperimentConfig & RunSettings

          

            
              

                필드명 (Field)
                타입 (Type)
                상세 기능 설명 (Specification)
              

            
            
              

                programming_language
                string
                AI가 개조할 소스 코드의 프로그래밍 언어 지정. Python, Verilog, C/C++, CUDA, Julia 등 독해 가능한 모든 언어 지원.
              

              

                max_programs
                int32 (필수)
                전체 진화 세션 동안 생성 및 채점할 파이썬 코드 세대 개체군의 총 수 (예: 10, 100, 1000).
              

              

                concurrency
                int32 (필수)
                병렬 소스 코드 생성기 동시 구동 수. 30 이하로 유지 시 쿼타 및 레이트 리밋 안정적 유지.
              

            
          

        


        
        

          
(2) GenerationSettings (다중 LLM 앙상블 & 프롬프트 문맥)

          

            
              

                필드명 (Field)
                타입 (Type)
                상세 기능 설명 (Specification)
              

            
            
              

                context
                string
                LLM 변이 생성을 위해 직접 주입되는 최적화 프롬프트 힌트 및 제약 조건 (최대 ~200k 토큰 커버).
              

              

                models
                repeated ModelConfig
                각 LLM 모델별 name, weight (상대 가중치 비율), temperature 조율. Flash(속도)+Pro(지능) 조합 앙상블 구동.
              

            
          

        


        
        

          
(3) EvolutionSettings (Island Architecture 기반 Local Optima 정체 탈출)

          

            reset_interval (int32): Island Architecture 기반 개체군 Reset 주기

            AlphaEvolve는 여러 하위 개체군 그룹(Island)을 병렬로 운영합니다. 진화 탐색이 특정 점수대(Local Optima)에 오랫동안 갇혀 정체되면, reset_interval 주기마다 해당 Island의 개체군을 Reset하고 시드 아이디어를 재배치함으로써 완전히 새로운 아이디어 구도로 변이를 강제 전환합니다.
          

        


        
        

          
(4) AlphaEvolveProgramContent & AlphaEvolveSourceFile (다중 파일 지원)

          

            files (repeated AlphaEvolveSourceFile): 대규모 다중 파일 프로젝트 진화

            단일 파이썬 파일뿐만 아니라, `path`("main.py", "utils.py"), `content`("소스코드 내용"), `program_language`("python"), `description`("파일 역할") 필드를 갖는 소스 파일 배열을 패키징하여 여러 파일로 이루어진 복합 소프트웨어 패키지 전체를 동시에 AI 개조하고 진화시킵니다.
          

        


        
        

          
(5) AlphaEvolveProgramEvaluation & Insights (다중 채점 & 피드백 주입)

          

            scores (AlphaEvolveScores) & insights (repeated AlphaEvolveInsight)

            - scores: [{"metric": "accuracy", "score": 0.95}, {"metric": "latency", "score": -42.5}] 다중 목표 수치 채점

            - insights: [{"label": "memory", "text": "Line 32 메모리 병목 경고"}]

            Insights 피드백 문자열은 백엔드에서 수집되어 다음 세대 LLM 프롬프트에 직접 주입됩니다. 단순 점수 숫자가 아닌 문맥적 원인을 전달하여 AI 코딩이 똑똑하게 개선되도록 안내합니다.
          

        


      


      
      

        

          ⚙️ 3. Evaluator Infrastructure Architecture Patterns (평가기 구축 파이프라인)
        

        

          평가는 기업의 자체 인프라에서 격리 실행됩니다. 알파이볼브 권장 3단계 원칙: Validation (문법 검증) ──> Verification (정확성 검증) ──> Evaluation (실측 성능 채점)
        


        

          

            Simple

            단일 머신 또는 Cloud Run 컨테이너에서 Virtualenv/Subprocess를 이용해 순차/독립 평가.
          

          

            Medium

            Cloud Run 병렬 가상환경에서 후보 솔루션을 팬아웃(Fan-out)하여 수평 분산 채점.
          

          

            Complex (GKE)

            GKE 오케스트레이터가 문법 검증을 중앙 처리하고, 다중 Cloud Run 평가기로 분산 채점.
          

          

            Hardware & 3P SaaS

            Verilog EDA 시뮬레이터, 하드웨어 카드, 3파티 검증 툴셋으로 디스패치하여 실시간 연동.
